Server architecture

控制面与运行时分离，
但共享同一套租户与审计

运行时：每租户一个 dsh

Per tenant
独立运行时

独立容器/进程、独立 DSH_HOME、独立卷、独立网络策略；试用租户可共享池，但禁用 shell/终端。

Runtime Agent
mTLS ⇄ stdio

控制面 ↔ Runtime Agent 走 mTLS；Runtime Agent ↔ dsh 走 stdio JSON-RPC；会话/工具/审批/事件都通过公开 SDK。

# 控制面 → 运行时（设计契约） POST /runtime/sessions # 创建会话（tenant/user/roles/capability token） GET /runtime/sessions/:id/events # SSE：assistant.delta/tool/approval/done POST /runtime/sessions/:id/prompt POST /runtime/approvals/:id # approve / deny # Runtime Agent → dsh（stdio JSON-RPC） initialize → session.create → session.prompt → session.event* → approval.request → approval.resolve
关键隔离：运行时没有控制面数据库凭据；只通过本地 socket/HTTP 调控制面内部 API，mTLS + 短时 capability token。会话归属 session_id → user_id，跨用户 resume 直接拒绝。
04
Runtime & agents

dsh 是发动机，
OpsAgent 是方向盘和仪表盘

不 fork agent-loop，不把内部 src 当扩展点。平台通过固定版本的 dsh、profile/bundle patch、defineTool、SDK JSON-RPC、审批钩子和会话事件，构建可升级的智能体能力。

Extension
薄 bundle

opsagent-runtime profile + Cordis patch；连接器工具、场景、Commander、Host Agent 桥都以插件方式接入。

Protocol
SDK JSON-RPC

会话 create/resume/prompt、事件流、审批、工具结果；不依赖 dsh 内部实现。

Models
LLM Gateway

OpenAI 兼容（chat/completions + responses）与 Anthropic Messages；平台 Key + 租户 BYOK；配额与审计。

三类 Session

Session职责工具面限制
Commander事件定级、拆任务、派发、证据汇总、根因/审批/报告只读运维工具 + 编排工具无 shell；R2+ 审批
Specialist指标/日志/DB/K8s/网络分析只读连接器工具、知识检索无写操作、无任意命令
Host CLI服务器本地对话、诊断、报告本地只读动作 + 服务端 LLM普通用户；R2+ 不能本地批准

一次会话如何工作

01创建控制面签发 capability token，Runtime Agent 启动会话
02提示模型规划；工具调用进入审批/沙箱
03工具连接器 / Host Agent / 知识检索，结果结构化
04事件SSE 回流到 Web；审批卡片到企业微信
05产物报告、证据、知识草稿；审计落库
Commander 不是“更大的模型”。它复用 dsh 的会话与工具，但把事件拆成 Incident/Ticket/Assignment，把结论拆成 Evidence/Hypothesis/Approval；模型不能直接执行 shell。

服务器上的受控操作员，

Communication

每一条链路，
都有身份、方向与审计

平台不使用“一个 WebSocket 到处跑”的简单方案；不同链路按信任边界选择协议，Agent 永远只主动出站。

07
Data & knowledge

本地优先的数据，
可热更新的知识

插件数据解决“查询快、对端稳”；知识解决“经验复用、越用越准”。两者都按租户隔离，都有版本、配额和审计。

插件数据沉淀

Local first
读本地，过期回源

插件声明 storage.datasets；平台自动建库；查询先读本地，stale/缺失才回源对端；写操作实时。

Lifecycle
自动清理，不占满磁盘

默认 30 天 / 单连接器 5GB；TTL、行数、配额；dry-run、清理审计；不删知识/审计/审批。

查询策略行为适用
local_first本地新鲜直接用；过期/缺失回源默认，兼顾速度与一致性
live_first优先实时，失败回本地强实时告警/变更
local_only只读本地，不访问对端隔离/断网/审计场景
live_only只读对端，不落本地敏感/一次性查询

知识：四类来源

Plugin
插件数据

每日增量 + 每周深度钻取；基线/拓扑/模式。

Docs
知识文档

PDF/Word/Excel/MD/HTML/CSV；ACL/版本/删除同步。

Conversation
用户对话

租户统一开关；脱敏；历史显式回溯。

Platform
平台运行

巡检/场景/事件产物；证据引用。

知识热更新机制

01发布知识管理员审核通过，生成 vN
02索引pgvector 新版本索引/别名原子切换
03通知Redis/SSE knowledge.published
04失效Runtime 清租户知识缓存
05生效下一 turn 的 knowledge.search 读 vN
06回滚切回上一版本，引用仍可追溯
No restart
不重启运行时

知识以版本化索引 + 工具查询的方式更新；运行时不需要重启，下一 turn 生效。正在生成的回答使用调用时的版本，引用带 kbVersion。

Guardrails
不会“悄悄换答案”

发布/修改/归档都要审核；旧版本在新版本发布前继续可用；冲突保留证据；租户 ACL 不放大。

知识不是把文档塞进 prompt。检索返回片段 + 来源 + 版本 + 置信度；Agent 必须引用；没有证据的结论只作为假设。
08
Scenarios & creation

把排障经验做成可复用场景，
把非标平台做成可安装插件

场景是“有输入、有步骤、有审批、有产物”的运维流程；创造模式用 dsh 的 cordis preset 自动生成可安装的 Cordis connector bundle，而不是只生成一份 manifest。

场景

Inspection
巡检

手动/定时；平台健康 + 租户系统；报告/证据/趋势；异常自动告警。

Metrics
指标异常分析

PromQL/ClickHouse/SQL；基线偏离、同比/环比、上下游关联。

Diagnosis
告警根因/故障诊断

指标+日志+变更+主机证据；假设/根因/处置建议。

阶段能力权限
草稿创建者编辑、测试、版本化创建者
角色可用同角色成员运行；默认发布范围创建者 / 角色
租户共享全租户角色可用租户管理员审批
平台共享进入平台目录，其他租户可安装租户管理员审核；平台管理员只治理/下架

创造模式：完整继承 dsh

01目标平台/API/凭据引用
02探查OpenAPI/端点/鉴权
03生成dsh cordis 写 Cordis bundle + SDK 代码 + tests + manifest
04沙箱plugin_manager 安装到 disposable profile；cordis_inspect 验证
05审核租户管理员 + 安全扫描
06灰度租户 profile 观察/转正/回滚
Inherit
不另造生成器

使用 dsh 的 cordis preset、创造模式 skills、plugin_manager、cordis_inspect_*；OpsAgent 只提供 Connector SDK、模板、沙箱编排和审核/灰度。

Never auto-publish
生成物不能直接进生产

先沙箱安装、inspect、跑契约测试；测试未过不能提交；审核通过后才进租户 profile。

长任务与无人值守巡检

01调度cron/手动创建持久任务
02检查点范围/指标/日志/报告
03心跳租约/超时/恢复
04告警平台健康/租户系统异常
05接管暂停/恢复/人工接管

长任务不是“一个会话挂一天”：任务实体、检查点、心跳、预算和恢复都在平台侧；运行时重启后从最近检查点继续。

Commander：证据优先的事件指挥

Commander 选择性 fork/裁剪 dsh-superagent：保留 Trigger/Ticket/Assignment、Policy、Effects/Outbox 骨架，替换为 Incident/Evidence/Hypothesis/Approval 与 Host/Connector Executor；每租户一个实例，不直接接 research bundle。

Incident
事件聚合

严重度、影响面、时间线、SLA；一个 Incident 多 Ticket。

Evidence
证据板

Host/Connector/Log/Metric/Change；来源、时间、哈希、置信度。

Approval
审批

R2/R3；Web/企业微信同一审批单；人工接管。

Executor用途安全
HostAgentExecutor客户端 Agent 只读诊断/证据签名指令；无 shell；超时/心跳
ConnectorExecutorProm/Zabbix/ClickHouse/DB 并行查询只读凭据/参数化查询/限流

Security

默认不信任，
每一步都可审计

平台安全不是“加一个登录页”，而是身份、租户、工具、网络、凭据、审批、模型、Agent 八个面同时约束。

面控制
身份LDAP + 本地管理员 break-glass；无 OIDC；HttpOnly 会话；Origin/CSRF。
租户PostgreSQL RLS；每租户运行时/卷/密钥/出口；平台管理员不读会话正文。
RBAC9 个内置角色；多角色并集；租户管理员配插件/授权；工具级双校验。
审批R0/R1 自动；R2 人工；R3 变更单；审批拒绝/超时/回执全审计。
Agent默认 root + 动作注册表；无裸 Shell；路径/参数白名单；1 天快照；签名指令。
Commander无 shell；类型化工具；人工 break-glass 不进模型；证据/假设/审批。
凭据Vault/KMS；运行时短时 token；不写 prompt/日志；轮换。
模型LLM Gateway；租户配额；BYOK；提示注入内容视为不可信数据。
供应链dsh 版本 pin；bundle/技能包签名；创造模式沙箱；未签名拒绝。
审计登录/租户/成员/工具/审批/知识/消息/任务/Agent 指令；180 天热存 + 归档。
三个“不允许”：不允许平台管理员默认读租户会话正文；不允许 Agent 执行任意 Shell；不允许分享/安装放大权限。

13
What is different

六个真正的差异点

不是把“大模型 + 监控”拼在一起，而是把运行时、数据、知识、审批、主机 Agent 和事件指挥做成一套可演进的系统。

01
dsh 原生，不 fork

固定版本 + 薄 bundle + 公开 SDK；升级可控，能力跟随 dsh，而不是维护一个私有分支。

02
创造模式真正“生成插件”

完整继承 dsh cordis，输出可安装 Cordis bundle；沙箱 profile + plugin_manager + cordis_inspect 验证，不是只生成 manifest。

03
Commander：证据优先

Host/Connector/Specialist 三路取证；Incident/Evidence/Hypothesis/Approval；模型只负责编排和假设，不直接拿 shell。

04
Local-first 插件数据

插件自动建库，读本地、过期回源，30 天/5GB 自动清理；既快又不把平台变成另一个时序库。

05
四来源知识 + 热更新

插件/文档/对话/平台运行统一沉淀；知识管理员审核；版本化索引热更新，不重启运行时。

06
多租户 + Agent 无 shell

每租户运行时/Commander；RLS/KMS/审计；Host Agent 默认 root 但动作门控；人工 break-glass 不进模型。

平台的最终目标：标准故障由 Commander 在分钟级完成跨源取证与根因确认；长尾问题由 Host Agent/连接器/创造模式持续扩展；每一次事件都沉淀为可复用知识，而不是一次性对话。

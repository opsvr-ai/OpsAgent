01
Decisions

技术选型：
为什么是 Go + 单二进制

目标主机是生产 Linux 服务器：不能带 Python/Node 运行时，不能依赖系统库版本，不能要求内核模块。Go 的静态编译、跨平台、并发与 gRPC 生态最匹配。

选型决定理由 / 边界
语言Go 1.24+（CI 固定 minor）静态二进制、交叉编译、低运行时依赖；团队可维护；不用 Rust 的编译/生态成本，不用 Python/Node 的运行时依赖
进程opsagentd（root daemon）+ opsagent（普通用户 CLI）daemon 内置 Agent Runtime；CLI 只通过 Unix socket 请求
Agent RuntimeCloudWeGo Eino ADK：ChatModelAgent/ReAct + 自定义 Tool + compose Graph；≤8–12 步、Token/时长预算Apache-2.0；pin v0.9.x；禁用 DeepAgent shell/python 工具
模型服务端 LLM Gateway（OpenAI 兼容 tool calling）；短时模型 tokenAgent 不持有厂商 Key；租户配额/审计在服务端
部署类型化 deploy.* 动作；签名 DeployOrder/制品；预检、canary、回滚R3；变更单/维护窗口/审批；不做任意 Shell
构建CGO_ENABLED=0，静态链接，-trimpath -ldflags "-s -w"无 glibc 依赖；x86_64/aarch64 可交叉编译；镜像/包体积可控
传输gRPC over HTTP/2 + mTLS双向流、protobuf、成熟拦截器；Agent 主动出站
本地存储SQLite（modernc.org/sqlite，纯 Go）+ zstd 快照无 cgo；WAL；单文件迁移；ring/分区表；1 天保留
OS 集成systemd D-Bus + /proc + /sys + journald + dpkg/rpmLinux first；不加载内核模块，不依赖 eBPF；容器只读元数据
CLICobra + Bubble Tea（交互式 chat）命令可脚本化；chat 有 TUI；不把模型/凭据放本地
配置/密钥YAML 配置 + 文件/TPM 私钥；证书 mTLSjoin token 一次性；私钥 0600；不进日志/环境变量
打包deb/rpm + tar.gz + systemd unit私有化优先；签名包；版本固定；可回滚
可观测stdlib log/slog JSON + journald + Agent 自身健康不引入重日志框架；不监听本地 HTTP 管理端口
Why Go
单二进制、低依赖

生产机不需要预装 runtime；静态编译、交叉编译、gRPC 与并发采集成熟。

Not eBPF v1
不加载内核模块

v1 用 /proc、systemd、journald、包管理；eBPF 仅作为后续可选增强，避免内核/发行版兼容风险。

Not root shell
root 只做受控动作

daemon root 是为了读取系统信息；执行器按动作注册表跑固定动作，不给任意 shell。

客户端是轻量 Go LLM Agent，不是纯主机代理。内置 CloudWeGo Eino ADK Runtime（Wake → Context → Plan → Act → Verify → Report → Sleep）；LLM 通过服务端 LLM Gateway，不把模型 Key/Node 运行时放到主机。它受服务端 Commander 控制；日常巡航/异常分析/部署都由签名策略与类型化工具约束。服务端 Commander 使用 dsh（P1.6 选择性 fork dsh-superagent）。

智能体框架选型对比

方案能否满足结论
dsh on hostNode 运行时、每主机部署 dsh、模型 Key/升级复杂不采用：太重，适合服务端 Commander
LangChainGoGo 生态，但抽象多、迭代快、工具执行控制不够显式不采用：不适合 root Host Agent 的强审计
Eino（CloudWeGo）Go 原生 Agent 框架：ADK/ReAct、Tool、HITL、compose Graph、callbacks；Apache-2.0，13k+ stars，v0.9.22（2026-10）采用：最匹配；pin 版本 + 薄封装 policy/executor
ADK Go（Google）v2.7.0；需 Go 1.26.10；云原生/Gemini 优先，较新不采用：Go 版本门槛高、偏重、版本较新
OpsAgent 薄封装不改框架核心：Tool 包装、Policy、审批、证据、部署执行采用：安全边界在 OpsAgent，不在模型
服务端 Commanderdsh + 选择性 fork dsh-superagent；多 Agent 编排采用：与客户端 Runtime 职责分离
02
Process model

两个进程，
一条本地 socket，零入站端口

daemon 常驻、root、无网络监听；CLI 以登录用户运行，通过受权限保护的 Unix socket 调 daemon；服务端指令由 daemon 主动出站 mTLS 领取。

opsagentdroot；systemd Type=notify；Agent Runtime/策略/工具/传输
opsagent CLI普通用户；Unix socket + SO_PEERCRED；chat/诊断/报告
Agent GatewaymTLS 长连接；签名指令；遥测/回执
Local store/var/lib/opsagent：SQLite + ring + snapshots
systemdunit、服务状态、journald、重启策略
OS / Apps/proc /sys /etc 日志、包、端口、进程
# 文件布局 /usr/local/bin/opsagentd # root daemon /usr/local/bin/opsagent # CLI，普通用户 /etc/opsagent/agent.yaml # 0600；IP 明文，认证字段加密 /etc/opsagent/join-token # 一次性，0600，注册后删除 /var/lib/opsagent/agent.db # SQLite WAL /var/lib/opsagent/ring/ # 高频数据/快照 /var/lib/opsagent/pki/ # 设备证书/私钥，0600 /run/opsagent/agent.sock # daemon ↔ CLI

systemd 权限模型

# 方向示意；P0 在目标发行版实测 [Service] User=root ExecStart=/usr/local/bin/opsagentd --config /etc/opsagent/agent.yaml Type=notify Restart=on-failure RestartSec=5 NoNewPrivileges=true PrivateTmp=true ProtectSystem=strict ProtectHome=true ReadWritePaths=/var/lib/opsagent /run/opsagent ReadOnlyPaths=/etc /usr /proc /sys /var/log CapabilityBoundingSet=CAP_DAC_READ_SEARCH CAP_SYS_PTRACE RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 CPUQuota=50% MemoryHigh=192M MemoryMax=256M TasksMax=64 IOWeight=50 OOMScoreAdjust=200 Environment=GOMEMLIMIT=200MiB GOMAXPROCS=2 GOGC=50

安装参数

# 安装时通过 CLI 传入服务端 IP、租户、认证材料、资源限额 opsagent install \ --server 10.20.30.40:8443 \ --tenant t-1001 \ --join-token-file /root/opsagent-join-token \ --ca-cert /root/opsagent-ca.pem \ --cpu-quota 50% \ --memory-max 256M

--server 支持 IP:port 或域名；生产禁止跳过 CA 校验。--join-token 可直接传，但更推荐 --join-token-file/stdin，避免进入 shell history/ps。

资源限额

项默认作用
CPUQuota50%最多半个核；空闲目标 <1%
MemoryHigh / Max192M / 256M软/硬上限；超限回收/降级
GOMEMLIMIT200MiBGo 堆软上限，避免 OOM
GOMAXPROCS2限制并行，避免抢业务 CPU
TasksMax / IOWeight64 / 50限制进程数/IO 权重
OOMScoreAdjust200Agent 先于业务被 OOM
Eino 预算8–12 步 / 12 次模型调用单次分析/部署有界

配置与敏感信息加密

# /etc/opsagent/agent.yaml（字段级加密，非整文件） server: address: "10.20.30.40:8443" # 明文；IP 不加密 ca_file: "/etc/opsagent/ca.pem" tenant: id: "t-1001" auth: gateway_token: "enc:v1:..." # AES-256-GCM join_token: "enc:v1:..." # 仅注册重试；成功后删除 limits: cpu_quota: "50%" memory_max: "256M"

AES-256-GCM、每字段随机 nonce、AAD 绑定 tenant/server/field；master key 优先 TPM2/OS keyring，否则 0600 文件；私钥 0600/TPM；配置 0600 原子写；日志脱敏。IP/端口/租户/CA/限额明文，认证材料密文。

Root
root 但不是全权 root

保留读取/诊断所需能力；systemd capability bounding set；不加载模块、不写业务目录、不开放入站端口。

CLI
普通用户

只能通过 0660 socket + peer credentials 调用；R2+ 只能发起申请，不能本地批准。

03
Code structure

模块边界，
按“谁能做什么”拆

代码按能力分目录，不按技术层堆文件；动作注册表、发现、采集、传输互相不越权。

包/命令职责关键约束
cmd/opsagentd守护进程入口、systemd notify、信号、生命周期不写业务逻辑
cmd/opsagentCLI：status/chat/discover/diagnose/report只调 Unix socket
internal/configYAML 解析、默认值、校验、环境覆盖拒绝未知字段；不打印 secret
internal/agentEino ADK Agent、ChatModelAgent、Runner、interrupt/resume≤8–12 步；只注册 OpsAgent Tool
internal/llmLLM Gateway 客户端、tool calling、重试不落模型 Key；租户 token
internal/deployDeployOrder、制品校验、预检、canary、回滚R3；签名制品；无 Shell
internal/identityjoin token、CSR、证书轮换、私钥存储0600；优先 TPM/OS keystore
internal/discoveryOS、systemd、包、端口、进程、容器、应用、配置/日志只读、限路径、限时、证据
internal/collector5s/30s/5m 指标、服务状态、日志签名环形缓冲、资源限额
internal/storeSQLite schema/迁移、ring、snapshot、配额WAL；1 天/1GB/2%
internal/policy动作注册表、R0–R3、路径/参数白名单默认拒绝
internal/executor诊断动作、进程栈、日志尾、配置读direct exec；无 shell 拼接
internal/transportgRPC/mTLS、注册、心跳、指令、回执只出站；nonce/过期
internal/knowledge应用画像、归属、本地排障缓存服务端主数据
internal/update签名包校验、原子替换、回滚未签名拒绝
proto/agent/v1AgentCommand/Result/Evidence/Heartbeatprotoc 生成；版本兼容
依赖原则：gRPC/protobuf、modernc sqlite、zstd、go-systemd dbus、Cobra、Bubble Tea、x/sys；不引入 ORM、不引入重量级插件框架。所有外部命令（rpm/dpkg/systemctl）都走固定 argv，不经过 shell。
04
Discovery

发现不是扫全盘，
是多信号收敛

发现的目标是“应用画像”，不是“文件索引”。每条结论必须有来源、置信度和证据；不确定就不自动绑定。

信号采集方式产出
OS / 内核/etc/os-release、uname、/proc/cpuinfo、/proc/meminfo、/proc/diskstatsHostProfile
systemd 服务D-Bus ListUnits/GetUnit；无 systemd 时降级ServiceInventory
包rpm -qa --qf / dpkg-query -W（固定 argv）PackageInventory
端口/进程/proc/net/tcp* + inode→/proc//fd；/proc//stat/cmdlineServiceInstance
容器cgroup v1/v2 元数据；默认不接 docker/containerd socketContainerInstance（可选）
应用指纹unit ExecStart、工作目录、jar/package.json、Nginx 配置、进程 cmdline、版本文件AppInstance + confidence
部署方式systemd / 容器 / 裸进程 / 静态站点；启动用户、工作目录、EnvironmentFile 键名（不读值）DeploymentProfile
配置/日志应用目录、unit、常见路径白名单；只读元数据/哈希/尾部ConfigLogMap
运维工具客户端进程/包/unit 特征：zabbix_agentd、node_exporter、filebeat、telegraf、falcon-agentOpsToolClient
依赖已有连接、父子进程、配置中的上游地址（只读解析）DependencyEdge
Limits
发现预算

最多 N 个目录、单文件最大 1MB、总时长 60s、并发 4；超预算标记 partial，不静默继续。

Confidence
不猜

应用实例至少两个独立信号；低置信度只作候选；应用/数据中心冲突进入复核。

应用识别例子

signalsystemd unitExecStart=java -jar order-service.jar
signal端口8080 listening → PID
signal配置/日志/opt/order/conf、/var/log/order
resultAppInstanceJava/Spring Boot，confidence 0.92
bindCMDBIP/主机名 → 订单中心/华东-1
05
Collection & storage

小颗粒度采集，
被磁盘预算驯服

高频数据留在本地环形缓冲，服务端拿摘要/异常窗口/按需快照；不把主机变成第二个时序数据库。

频率数据本地保留上传
5sCPU、内存、load、磁盘 IO、网络、TopN 进程1h异常窗口
30s服务状态、端口、连接、应用健康、线程/队列6h摘要/异常
5m配置哈希、日志错误签名、依赖/版本变化24h变化/摘要
按需线程栈、日志尾、连接详情、配置片段24h / 200MB任务结果
SQLite
WAL + 分区表

metrics_fast/service_samples/config_events；按时间分区/滚动删除；迁移带版本。

Disk guard
min(1GB, 2%)

80% 清旧高频；95% 停高频并告警；快照 zstd；不允许写满磁盘。

不做的采集：不做全量日志上传、不做持续 tcpdump、不做全盘文件索引、不做无上限的 eBPF。采集器自身 CPU <1%、RSS <100MB、写入 <5MB/s。
06
Protocol

指令、结果、心跳：
全部 protobuf，全部签名

gRPC 双向流是传输载体，业务层仍是“带 ID/过期/签名”的指令信封；模型和平台不能直接下发自由文本。

// proto/agent/v1/agent.proto（摘要） service AgentGateway { rpc Connect(stream AgentMessage) returns (stream GatewayMessage); } message AgentMessage { oneof body { Hello hello = 1; Heartbeat heartbeat = 2; CommandResult result = 3; TelemetryBatch telemetry = 4; EvidenceBatch evidence = 5; } } message GatewayMessage { oneof body { Welcome welcome = 1; SignedCommand command = 2; PolicyUpdate policy = 3; Ack ack = 4; } } message SignedCommand { string command_id = 1; string tenant_id = 2; string host_id = 3; string action_id = 4; bytes params_json = 5; string policy_version = 6; google.protobuf.Timestamp issued_at = 7; google.protobuf.Timestamp expires_at = 8; string nonce = 9; bytes signature = 10; // Ed25519 over canonical fields }
Verify
Agent 校验 8 项

mTLS 证书、签名、tenant/host、动作白名单、参数 schema、policy 版本、过期、nonce/replay。

Idempotent
command_id 幂等

重复指令返回上次结果；执行前写 WAL；超时/重启可恢复；结果签名回传。

动作注册表示例

action_id实现风险限制
diag.snapshot采集指标/服务/端口/连接R0最大 50MB；脱敏
diag.log_tail读日志尾部R0路径白名单；2MB
diag.thread_dumpJava/Go 栈R0PID/超时 30s
diag.config_read配置片段R0路径白名单；不读密钥
change.restartsystemd restartR2审批 + 回滚点
07
Security

先假设会被打，
再设计 agent

Agent 在每台生产机上运行，必须按“本机可能被攻破、网络可能被劫持、服务端可能被冒充”设计。root 不是信任，签名和动作注册表才是。

威胁控制
伪造服务端指令双向 mTLS + Ed25519 签名 + KMS/HSM 托管 + 动作白名单
重放旧指令nonce + 短过期 + 本地 replay cache + command_id 幂等
错发租户/主机证书绑定 host/tenant；信封二次校验
日志/配置提示注入内容视为不可信数据；模型只提议，执行器按动作执行
本机恶意用户CLI Unix socket + SO_PEERCRED；R2+ 服务端审批；不共享 root
密钥泄露私钥 0600/TPM；短证书；轮换/吊销；异常行为检测
供应链二进制/包签名、SBOM、cosign、版本固定、灰度
Agent 自身漏洞最小依赖、静态分析、fuzz、无入站端口、systemd 限制
人工 break-glass 不进模型。紧急情况由人通过 SSH/跳板机操作，平台审计；不给 AI 一个“紧急 root shell”的例外。
08
Packaging

安装、升级、回滚，
都按“可撤销”设计

首版不依赖容器运行 Agent；用 deb/rpm/tar.gz + systemd，适合私有化银行/企业环境。

产物内容用途
deb / rpmopsagentd、opsagent、systemd unit、默认配置RHEL/Rocky 9、Ubuntu 22.04/24.04、Debian 12
tar.gz静态二进制 + unit + install.sh离线/无包管理环境
SBOM / cosign依赖清单、签名供应链审核
systemd unitType=notify、Restart、hardening常驻与自恢复
Upgrade
下载 → 验签 → 原子替换 → 健康检查 → 回滚

默认不自动升级；按租户灰度；失败保留上一版。

Skills/tools
签名包 + 本地缓存

从服务端拉取；版本固定；未签名拒绝；离线用缓存。

不要用容器跑 Host Agent 作为默认方案。它需要主机 root、systemd/journal/包信息；容器会引入挂载/权限/升级复杂度，除非客户明确要求。
09
Testing

在真实发行版上验证，
不靠“本地能跑”

Agent 的 bug 可能影响生产机；测试必须覆盖多发行版、root/普通用户、网络断开、磁盘满、时钟偏移、恶意输入。

层内容环境
单元解析器、动作 schema、路径白名单、签名/重放、存储迁移Go test + fixtures
集成systemd/包/端口/进程发现、采集、SQLite、gRPCRocky/Ubuntu/Debian VM 或容器
端到端注册→发现→采集→异常→签名指令→证据真实 VM + mock Gateway
故障注入kill/重启、断网、磁盘满、时钟偏移、证书过期、Gateway 5xxVM/混沌脚本
安全伪造/重放/错发租户/路径穿越/命令注入/提示注入红队用例

目标指标

<35MB静态二进制（目标）
<100MB常驻 RSS
<1%空闲 CPU
<60s首次发现（目标）

目标以 P0/P2-A 实测校准；不以牺牲采集完整性/安全性换指标。

10
Roadmap

先只读可用，

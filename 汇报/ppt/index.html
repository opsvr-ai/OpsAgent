OpsAgent / principles05 / 25
System architecture

控制面、运行时、现场执行三层协同

一条向上是事实，一条向下是命令。
控制面定义谁能做什么、在哪个应用系统做、是否需要审批。
运行时把问题拆成计划，把计划变成工具调用，把结果变成证据和结论。
操作系统智能体把本机发生了什么，变成结构化事实回传平台。
边界：智能体不是平台，平台也不是智能体；前者提供现场，后者提供调度和治理。

Fault boundary · definition

故障定界：先确定边界，再收敛根因

不是让模型看一眼告警直接给答案。
Step 01 / Boundary
影响范围到哪里？

哪些节点、应用、端口、连接边受影响；哪些是边界外依赖。

Step 02 / Root cause
根因最可能在哪？

从异常节点、拓扑上游、时间顺序和补采证据中收敛候选。

Difference / 01
结果 ≠ 原因

CPU 高、连接拒绝可能只是下游症状。

Difference / 02
边界是可计算的

沿真实访问关系向下游扩散，而不是凭经验圈范围。

Difference / 03
结论必须可验证

根因候选 + 证据 + 置信度，而不是一句自然语言。

OpsAgent / fault boundary16 / 25
Why old RCA fails

为什么“把告警丢给模型”效果不好

根因分析的质量，取决于输入的事实质量。
01
只有单点数据

只看一台主机，看不见上下游。

02
只有告警文本

没有进程、端口、连接和日志事实。

03
没有时间序列

不知道异常是先发生还是后发生。

04
模型没有约束

没有候选评分、证据引用和人工确认。

所以：不是换更大的模型，而是先换输入：现场事实 + 时间序列 + 访问拓扑 + 证据约束。
